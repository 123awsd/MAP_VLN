# Fig. 8：覆盖变化、跨区域恢复与地图更新

这一版按参考图分析后的三个具体问题重构：新增覆盖需要能直接看到，跨房间路线需要足够大，地图更新需要有前后对照。正文和原图尚未替换。

## 文件

- `fig8_mechanism_en.png`：英文预览。
- `fig8_mechanism_en.pdf`：论文用 PDF，184 × 101.2 mm，最小字号约 7.39 pt。
- `fig8_mechanism_en.svg`：自包含源文件，图像已嵌入；文字、轨迹、覆盖层、相机方向和图节点均为矢量。
- `fig8_scene.blend`：真实住宅场景，纹理已打包，保留整个多房间住宅，仅调整展示相机与色彩。
- `caption.tex`：对应英文图注。
- `render_scene.py`、`compose_figure.py`：重现脚本。
- `provenance.json`、`layout.json`：来源、示意边界与导出检查。

## 构图与机制

**Local retry**：在同一俯视视角、同一裁剪范围中展示两个观察姿态。灰色覆盖保持不变，第二个状态新增橙色覆盖；方向三角和短箭头显示视点变化。两次未检出和局部限制标在对应状态下，RGB 扶手椅图提供对象参照。

**Semantic recovery**：放大真实住宅中卧室—门口—客厅的空间关系，路线复用之前经过通道位置检查的示意路线。完整住宅保留在定位小图中，未参与区域降低对比；不是重新搭建一个只有两个房间的场景。任务在恢复期间保持相同。

**Verify & update**：从目标位置直接连接到两张同实例 RGB 观测。验证和 3D 实例关联发生于执行中，之后的物体地图以 Before / After 对照呈现。原有节点的位置和样式保持一致，新增节点和边显示为绿色。

## 示意与来源

- 原始场景为 HM3D `00166-RaYrxWt5pR1`，本版从 `../multiroom_redraw/fig8_textured_scene.blend` 重新设置近俯视相机进行渲染；真实网格、家具与住宅布局均保留。
- RGB 来源为 `画图/Habitat长指令执行/keyframes/00166_cushion_recovery_20261024/` 中已有的 `obs_000000.png`、`frame_000420.png` 和 `obs_000003.png`。图像通过 SVG 原生裁剪展示，没有生成式补绘。
- 路线、局部观察数量和覆盖分区是为了讲解设计的示意。灰色和橙色面片只解释重复与新增覆盖的区别，不是实测可见性，不表达定量置信度，也不表示矩形范围内没有遮挡。相机方向表示姿态在平面上的投影。
- 原始路线的 navmesh 检查仅用于通道位置参考，不构成飞行碰撞检查或算法实验结论。本版相机变更不改变世界坐标中的路线。
- 为说明新增实例，图中假设这个靠垫不在初始物体地图中。源运行中已经存在靠垫物体，不宣称该运行实际新增了图示靠垫。日志与原始数据未修改。

## 重现

在项目根目录执行：

```bash
blender -b -t 8 --python 画图/语义恢复与地图更新/mechanism_redraw/render_scene.py
/usr/bin/python3 画图/语义恢复与地图更新/mechanism_redraw/compose_figure.py
python 画图/语义恢复与地图更新/mechanism_redraw/finalize_export.py
```

PDF 导出步骤将嵌入的照片流压缩为质量 95 的 JPEG，保留原像素尺寸、透明蒙版和全部矢量文字/图形。SVG 保留原始 PNG 数据。
