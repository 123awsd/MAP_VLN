# 问题与解决

## GPU 在沙箱中不可见

- 现象：沙箱执行 `nvidia-smi` 无法连接驱动，但 PCI 设备可见。
- 用户确认：宿主机侧 `nvidia-smi` 正常。
- 当前判断：沙箱未映射 NVIDIA 设备，而非宿主机驱动损坏。
- 处理：不修改驱动；后续在实际 Conda/容器运行时重新验证。

### 结果

- 沙箱外 Habitat EGL 成功识别 RTX 5060 Ti 和驱动 580.126.09。
- 结论：宿主机驱动正常，确认为沙箱设备隔离。

## Habitat-Sim 0.3.3 与 Python 3.12 冲突

- 现象：Conda 的 0.3.3 Bullet 构建只提供 Python 3.9 变体。
- 处理：项目专属 Habitat 环境固定 Python 3.9.23；不影响其他环境。

## Boxer OWLv2 首次下载损坏

- 现象：早期受限网络产生部分文件，直接续传导致 zip 尾部不可读。
- 处理：只删除已确认损坏的 OWLv2 文件，从 0 字节重新下载。
- 验证：三个权重均能由 PyTorch 成功加载并已记录 SHA-256。

## Habitat-Lab 安装后的 Pillow 冲突

- 现象：Conda求解安装 Pillow 11.3.0，但 Habitat-Sim 0.3.3 要求 10.4.0。
- 处理：在项目专属环境固定 Pillow 10.4.0；Habitat/Habitat-Sim 导入成功。

## Docker Hub 基础镜像下载极慢

- 现象：CUDA基础镜像105MB层下载速度最终降到约20KB/s。
- 处理：安全中断，避免长时间无收益占用；没有遗留运行容器。
- 后续：优先配置项目级可选镜像源，或在FALCON正式Docker构建时复用已存在层继续拉取。

## 2026-08-23 桌面会话被 OOM 终止

- 现象：桌面/系统会话崩溃，但机器未重启；磁盘仍有约 179 GB，不是存储耗尽。
- 内核证据：8 GB swap 几乎耗尽后触发 OOM，杀死一个约 5 GB RSS 的 Chromium Python 进程。
- 共同诱因：当时另一个项目已有约 14 GB 的大型 Python 进程，本项目 OccuSG 编译又无并发上限地生成约 30 个 `cc1plus`，新增超过 10 GB 内存压力。
- 责任判断：本项目无上限编译是直接触发因素之一，不能归咎于沙箱或磁盘。
- 修复：`colcon --parallel-workers 1`、CMake/Make `-j2`，并增加 12 GiB 内存/2 GiB swap 预检。
- 复验：安全构建时只有 2 个 `cc1plus`，最低仍有约 22 GiB 可用内存，swap 未继续消耗，构建成功。

## RViz 容器无法连接 X11

- 现象：首次启动显示 `Authorization required` 和 `could not connect to display :1`。
- 原因：`/home/uav/.Xauthority` 是空文件，当前 GDM cookie 实际位于 `/run/user/1000/gdm/Xauthority`，且容器 hostname 不匹配原 cookie family。
- 处理：提取当前 display cookie，转换为 FamilyWild，保存到 Git 忽略的 `runtime/rviz.Xauthority` 并只读挂载到容器。
- 结果：RViz 1.14.26 正常启动；容器未映射 NVIDIA GUI 驱动，因此使用 llvmpipe OpenGL 3.1，显示功能正常但渲染性能低于原生 GPU。
- 录制和回放脚本会自动刷新 cookie，桌面重启后也无需手工运行 `xhost`。

## 相机倒着走、Box 不明显与点云遮挡

- 原因：Habitat 位置跟随与 FALCON 独立 yaw 轨迹可能不同向；且 optical 姿态曾直接用作 body odometry。
- 修复：默认面向实际移动方向，optical pose 仅用于深度建图，body pose 用于 odometry/path。
- 验证：最终 bag 中 97 个移动采样的前向对齐度平均值和最小值均为 1.0000。
- Box 只有 2 个是上游高置信融合阈值的真实结果，不是 RViz 丢消息；可视化改用 26 个去重候选的高亮线框，正式 2 个结果仍保留。
- occupied cloud 降为 1 px/alpha 0.22，depth cloud 和 candidate viewpoints 默认关闭。

## RGB 卡顿、Box 一次性出现且与房间错位

- 原因：旧 bag 只有 5 Hz RGB，同时包含大量高频规划 Marker；Box 来自另一次 episode 且融合 CSV 的时间全为 0。
- 修复：RGB 提升到 10 Hz，移除 `pos_cmd`、`position_cmd_vis`、`viewpoints` 录制；同次探索同时保存 Boxer 关键帧，按 `first_seen_ns` 回写 bag。
- 验证：RGB 实测 9.95 Hz，总消息 5,326；31 个 box 按 18 个事件渐进出现。
- 同回合对齐验证：Box 中心到 occupied map 最近距离中位数 0.036 m、最大 0.060 m，无超过 1 m 的房间外框。

## RGB 话题不断流但中段画面冻结

- 现象：轨迹 Marker 周期刷新时，第一视角会连续数秒保持同一画面，容易误判为回头路时 RGB 丢失。
- 证据：旧包 399 帧中有 159 对内容完全相同；冻结区间 odometry 位移为 0，最长 4.3 秒，说明是规划等待而非 ROS 时间戳缺口。
- 修复：FALCON 静止超过 0.5 秒后，Habitat 相机以 25°/s 原地扫描；移动恢复时立即面向真实位移方向。主 3D 默认关闭容易误导的规划轨迹，2D 窗口单独展示轨迹和 frontier。
- 验证：新包 400 帧、10.0 Hz，最长相同画面仅 0.4 秒；10 倍速回放完成后 RGB 最后一帧与两个 RViz 窗口均保留。
