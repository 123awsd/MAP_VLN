# 数据接口

## Habitat episode v1

目录包含 `manifest.json` 和 `frame_XXXXXX.npz`。每帧字段：

- `rgb`: H×W×3 uint8
- `depth_m`: H×W float32，米制
- `semantic`: H×W int32
- `position`: 世界系 XYZ，米
- `orientation_xyzw`: optical camera 到世界系的四元数
- `time_ns`: int64

当前相机内参：640×480，fx=fy=320，cx=320，cy=240。

## OccuSG occupancy grid v1

- `*.npy`: H×W int8，ROS OccupancyGrid 行主序；-1 unknown、0 free、100 occupied。
- `*.json`: resolution、origin、width/height、cell 统计和 source episode。
- 世界系为右手 Z-up；二维栅格使用世界 X/Y。

## OccuSG regions v1

`regions.json` 包含 region id、世界系 XY centroid、polygon、convex hull、area 和 adjacent ids。

## Scene graph v1

`outputs/scene_graph/<episode>.json` 包含 rooms、objects、room adjacency edges 和 semantic room type。Boxer 中心处于障碍内部而不落入自由空间多边形时，`room_assignment` 明确记为 `nearest_centroid_fallback`。

## ROS bag 可视化接口

默认最终 bag：`outputs/bags/hm3d_stage1_complete_v3_final.bag`。旧的 40 秒 `hm3d_stage1_scan_complete_final.bag` 实际是定时截断包，只保留作对照，不再称为完整探索。

- `/habitat/rgb`, `/uav_simulator/depth_image`
- `/uav_simulator/odometry`, `/uav_simulator/sensor_pose`
- `/pre_map_vln/agent_path`, `/pre_map_vln/box_markers`
- `/planning/bspline`, `/planning/travel_traj`
- `/planning_vis/frontier` 及 frontier point clouds
- `/voxel_mapping/occupancy_grid_occupied`, `/voxel_mapping/depth_pointcloud`
- `/hgrid/visulization_marker`, `/hgrid/visulization_markerarray`

`orientation_xyzw` 仍表示 optical camera 姿态，供深度建图使用；桥状态中的 `body_orientation_xyzw` 用于 odometry、RViz 机体箭头和 agent path。

`boxer_3dbbs_progressive.csv` 在 Boxer 原字段外增加 `first_seen_ns`、`last_seen_ns` 和 `support_count`。注入后的 `/pre_map_vln/box_markers` 每次发布当前已观测实例的累计 MarkerArray。

## Stage 2 task graph v1

`pre_map_vln.task_graph.v1` 包含 `tasks`、`edges` 和 `conditional_rules`。任务中的 `target.label` 是导航锚点，`verification_label` 是终止时实际验证对象；条件规则根据源任务 `found/not_found` 激活或跳过目标任务。读取时强制执行 schema、引用、DAG 和条件一致性校验。

## Stage 2 planning/execution

- `candidates.json`：每个 task 的自由栅格候选 pose、yaw、LOS 与局部代价。
- `joint_plan.json`：Subset-DP 选择的 task/candidate 顺序、A* 路径和固定顺序基线。
- `habitat_execution.json`：每次重规划、任务路径、RGB 帧范围、semantic pixels、found/not_found 结果和条件状态变化。
- `updated_scene_graph.json`：验证后的 box 状态、置信度和任务证据。
- `stage2_report.json`：统一自动验收报告。

## Stage 2 ROS bag

默认包 `outputs/bags/hm3d_stage2_complete.bag` 的主接口：

- `/stage2/rgb`, `/stage2/task_text`, `/stage2/task_status`
- `/stage2/executed_path`, `/stage2/global_tour`, `/stage2/local_path`
- `/stage2/candidate_poses`, `/stage2/selected_goals`
- `/stage2/semantic_boxes`, `/stage2/rooms`
- `/stage2/uav_pose`, `/uav_simulator/sensor_pose`
- `/voxel_mapping/occupancy_grid_occupied`

bag 使用同一模拟时钟同步 RGB、路径和状态。末帧之后 `rosbag play` 结束，但 RViz 进程继续保留。

## Stage 2 paper benchmark v1

`outputs/stage2/paper_benchmark/report.json`：

- `protocol`：scenes、seeds、task suites、methods、trial count 和几何/语义结论边界；
- `summary`：按方法聚合；
- `summary_by_suite`：按方法和任务类型聚合；
- `summary_by_scene`：按方法和场景聚合；
- `records`：270 条原始 trial；
- `failures`：生成或规划失败，正式验收要求为空。

每条 trial 包含任务/条件成功率、路径、2.5D 飞行时间、yaw 转角、观察质量、LOS、重规划次数和规划 wall time。`trials.csv` 是便于绘图/统计的软件无关扁平接口，`summary.md` 是自动生成的论文表格。
