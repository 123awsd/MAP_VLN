# 房间分割与 Habitat 真值对比

## 真值边界

HM3D example 提供 3D mesh、纹理、navmesh 和 semantic object annotations，但不随场景提供一张人工绘制、可直接作为精确房间多边形真值的 CAD 平面图。当前 example 的 Habitat semantic regions 有对象归属，但 region AABB/类别为空，不能作为可靠的房间边界。

可直接使用的官方几何对照是 Habitat `PathFinder.get_topdown_view()`：它从官方 navmesh 返回指定楼层的可通行地面。官方教程也使用该接口或 Habitat-Lab `get_topdown_map` 生成俯视图：

- https://github.com/facebookresearch/habitat-sim/blob/main/examples/tutorials/nb_python/ECCV_2020_Navigation.py
- https://github.com/facebookresearch/habitat-lab/blob/main/habitat-lab/habitat/tasks/nav/nav.py

navmesh 是机器人半径/高度约束下的可通行几何，不是人工房间标签。它会绕开床、柜子和不可站立区域，因此轮廓本身也可能有孔洞和凹槽。

该建筑含向下楼梯，Habitat navmesh 会保留楼梯可通行性。本项目的规划器是单层 2.5D，不声称支持楼梯或跨层导航；因此 navmesh 仅作官方几何对照，楼梯在本项目地图中必须被屏蔽。

## 双地图与全自动物体过滤

系统不再用同一张占据图同时承担避障和房间理解：

- `${episode}_grid` 是导航地图，保留所有观测障碍；
- `${episode}_structure_grid` 是房间结构地图，仅供 OccuSG 分割。

Boxer 融合后的全部 3D Box 会批量交给 Qwen3.7-Plus。Qwen 为每个实例输出
`structural_boundary`、`opening_boundary`、`interior_object`、`fixed_fixture` 或
`uncertain`，只有高置信度的室内物体和固定设施会从结构地图移除。策略保存在
`outputs/stage1/<episode>/structure_policy.json`，并记录模型、提示版本、费用和缓存状态。

实际过滤使用 3D 旋转框与深度端点的几何包含关系，不再错误地把 Boxer 类别编号
当成 HM3D 场景实例编号。墙、柱、门框及楼梯语义具有更高优先级；低置信度或遗漏实例
默认保留。结构图还会清理不能形成房间边界的孤立占据组件，导航地图始终不受影响。

OccuSG 对结构图统一使用 `decomp_threshold=1.8`。当前场景中原 R11/R13 在去除床等
家具影响后成为同一个约 25.63m² 卧室，不包含任何按床类别或房间 ID 编写的合并规则。

## 原问题

OccuSG 旧版从未分层的探索占据图得到多个家具诱发的源区域。旧场景图虽然给小区域写了 `parent_room_id`，但仍把它们保留在 `rooms`。

- R1、R4 属于 R2 bedroom；
- R6 属于 R10 living room；
- R7、R8 属于 R5 kitchen。

这造成三个问题：RViz 绘制内部碎片边界、规划候选携带碎片房间 ID、Qwen 恢复清单可能把同一房间看成多个房间。

随后的官方语义对齐又发现，旧 R13 的 5.60m² 斜形区域与 HM3D `stairs`/`stairs railing` 重合。楼梯深度点最低落到当前层以下约 2.7m，旧建图却把所有高度的深度射线压到同一张 2D 图，导致楼梯/楼梯井被误当成第 7 个房间。

## 规范化

`fuse_rooms_boxes.py` 现在输出两层表示：

- `rooms`：规范规划图，当前包含 5 个语义房间和 2 个 corridor；
- `geometric_regions`：9 个底层几何区域，仅用于来源追溯。

规范化过程执行：

1. 按 `parent_room_id` 聚合主房间与碎片；
2. 碎片物体迁移到规范父房间并记录 `source_region_id`；
3. 碎片邻接边重映射到规范房间 ID，删除自环和重复边；
4. 只在已经确认属于同一父房间的多边形之间跨越家具断口，生成一个显示外轮廓；
5. 保存 `polygon_components_xy_m` 与 `merged_from_region_ids`，不丢失原始证据；
6. Qwen inventory 显式拒绝 `room_fragment`，防止旧场景图再次泄漏碎片。

单层修复额外执行：

1. 只将世界高度 `0.15–1.8m` 的深度端点投影为当前层自由/占据证据；
2. 从 HM3D `semantic.txt` 识别 ID 445 `stairs railing` 和 ID 462 `stairs`；
3. 将同一楼梯的台阶与栏杆聚为物理楼梯组件，生成 0.20m 净距禁行区；
4. 不把楼梯旁小型、无物体、无邻接的残留孤岛当作目标房间。

当前自动结构分割摘要：

## 三图对照

运行：

```bash
cd "$(git rev-parse --show-toplevel)"
.envs/habitat/bin/python scripts/compare_room_segmentation.py
```

输出：`outputs/room_comparison/hm3d_stage1_complete_v3.png`，依次显示：

1. Habitat 官方 navmesh 可通行真值；
2. 本项目房间结构占据图；
3. 规范房间边界叠加官方 navmesh。

中图和右图的红色斜线区域是被明确排除的楼梯，可用于直接检查算法没有偷偷把楼梯当平地。

三图使用同一个 Falcon 坐标系、同一楼层和 0.05m 分辨率。该图用于诊断几何一致性，不能将 navmesh 称为人工房间语义真值。
