# 第五阶段：开源方法对比

## 1. 对比对象

主对比固定为 Open-Nav、VLN-Zero、SpatialNav 和 PRE_MAP_VLN。Open-Nav 是无预探索的连续零样本基线；VLN-Zero 是“快速探索—符号场景图—神经符号规划”的同类方法；SpatialNav 是使用预探索空间场景图的前沿方法。

外部方法与内部长期任务不能混为一张表：

1. 标准 R2R-CE 100 表使用同一组 episode、MP3D 场景、成功阈值和 NE/OSR/SR/SPL/nDTW。
2. HM3D 长时程表使用任务完成率、约束满足率、条件分支正确率、路径长度、重规划次数、VLM 调用次数、地图纠正率和恢复成功率。

## 2. 可复现状态

三套源码均固定提交并由 `third_party.lock.yaml` 管理。Open-Nav 与 VLN-Zero 必须共享项目内 `.envs/vlnce_legacy`，因为两者依赖 Habitat 0.1.7/Python 3.8；当前 PRE_MAP_VLN 的 Habitat 0.3.3/Python 3.9 环境不作修改。

RTX 5060 Ti 的计算能力为 `sm_120`，上游固定的 PyTorch 2.4.1+cu121 不带对应内核。旧环境可以运行 Habitat 和 CPU smoke test，但原版 GPU 感知不可直接执行。公平实验采用进程分离：旧 Habitat 进程维持官方动作和测量协议，现代项目进程承担本地开放词表感知；若报告原版 CPU 结果，必须明确标记。

Spatial-X 当前只发布了 SpatialNav raw agent。上游 README 仍注明安装说明、预探索/重建代码和生成的空间场景图数据未发布。因此：

- 论文原始结果标为 `SpatialNav (paper reported)`；
- 本项目可控复现标为 `SpatialNav-style (our reimplementation)`；
- 不得把后者写成官方复现结果。

## 3. 当前资产

- OpenNav_R2R-CE_100：100 episodes、10 个 MP3D 场景 ID，episode 文件随上游仓库提供。
- Open-Nav waypoint predictor：已下载到 Git 忽略的 `checkpoints/baselines/opennav/`。
- DD-PPO depth encoder：已下载到同一目录。
- torchvision ResNet-50 RGB encoder：已下载到项目内 `cache/torch/`。
- 两个权重均固定 SHA-256，并在下载脚本每次运行时校验，避免断点下载或缓存污染造成静默错误。
- MP3D：下载官方 14.9 GiB Habitat 压缩包后，只解压上述 10 个场景。
- SpatialBot、RAM 和 VLN-Zero 的额外大模型暂不重复下载；受控对比复用 PRE_MAP_VLN 的异步 OWLv2/Qwen 服务。

Open-Nav 的共享感知移植已用真实 Habitat RGB 验证：OWLv2 正确形成 Open-Nav 所需的方向化自然语言观察（中心 lamp、右侧 bed），首次调用含模型启动约 10.5 秒，后续调用使用常驻 worker。该移植只用 Qwen 做导航推理，逐帧目标检测完全在本地 GPU 完成。
旧导航进程通过 `CUDA_VISIBLE_DEVICES=""` 固定在 CPU，OWLv2 子进程通过独立变量重新绑定 GPU 0，规避 PyTorch 2.4.1 对 `sm_120` 的不兼容。

## 4. 命令

```bash
cd /home/uav/map_VLN/PRE_MAP_VLN
./scripts/fetch_dependencies.sh
./scripts/apply_external_baseline_patches.sh
./scripts/setup_vlnce_legacy_env.sh
./scripts/fetch_external_baseline_assets.sh
./scripts/link_external_baseline_assets.sh
.envs/habitat/bin/python scripts/extract_r2r_ce_100_scenes.py --dry-run
.envs/habitat/bin/python scripts/extract_r2r_ce_100_scenes.py
./scripts/run_vlnce_legacy.sh open-nav scripts/smoke_r2r_ce_scene.py
./scripts/run_opennav_smoke.sh
.envs/habitat/bin/python scripts/check_external_baselines.py
.envs/habitat/bin/python scripts/check_external_baselines.py --runtime
.envs/habitat/bin/python -m unittest tests.test_external_baselines
```

体检报告输出到 `outputs/baselines/readiness.json`。只有 `r2r_ce_100_execution=true` 才能启动标准数据集运行。

运行旧基线时必须通过 `scripts/run_vlnce_legacy.sh`，它会把 Hugging Face 和 Torch 缓存限制在项目内，避免写入用户级缓存或影响另一项目。
该入口从 Git 忽略的 `.secrets/dashscope_api_key` 注入凭据，并默认设置 DashScope OpenAI-compatible endpoint 和 `qwen3.7-plus`；密钥不会出现在命令参数、日志或 Git 中。
Qwen 请求默认关闭思考模式；实测极小连接请求由 235 tokens 降至 28 tokens。Open-Nav 移植的每次调用都会记录 model 和 token usage 到 `outputs/baselines/qwen_usage.jsonl`。
`smoke_r2r_ce_scene.py` 只验证数据、导航网格和 RGB-D 渲染，不调用 Qwen；`run_opennav_smoke.sh` 才会执行一个完整导航 episode 并产生 API 调用，两者不得混淆。
上游每步默认运行 `2 retries × 3 samples` 再做 thought fusion；首次完整 smoke 保留该逻辑，单 episode 共发生 65 次 Qwen 调用。项目入口为后续工程评测默认降为 `1 × 1`，可显著减少调用；复现论文逻辑时必须显式设置 `PRE_MAP_VLN_OPENNAV_RETRIES=2 PRE_MAP_VLN_OPENNAV_SAMPLES=3`，并在结果标签中注明。

## 5. 结论边界

源码可导入、模型可加载、单 episode smoke test、完整 100 episodes 评测是四个不同验收层级。当前报告必须逐级描述，不得把“源码和权重已就绪”表述为“官方结果已复现”。

## 6. 论文报告值（只作参考）

以下数字来自各论文，尚不是本机复现结果。三篇论文并非都使用完全相同的 episode 抽样与模型后端，因此该表用于确定量级和实验目标，正式结论以本项目同一份 R2R-CE 100 清单的重跑结果为准。

| 方法 | NE ↓ | OSR ↑ | SR ↑ | SPL ↑ | nDTW ↑ | 备注 |
|---|---:|---:|---:|---:|---:|---|
| Open-Nav GPT-4 | 6.70 | 23.0 | 19.0 | 16.1 | 45.8 | R2R-CE 100 |
| VLN-Zero | 5.97 | 51.6 | 42.4 | 26.3 | — | R2R-CE val-unseen；论文表给出完整 split |
| SpatialNav | 5.15 | 66.0 | 64.0 | 51.1 | 65.4 | R2R-CE 随机 100 条 |
| SpatialNav† | 4.21 | 73.0 | 68.0 | 53.4 | 69.3 | 使用 MP3D 真值空间标注的上界，不作为公平主对比 |

资料来源：

- Open-Nav: <https://arxiv.org/html/2409.18794>
- VLN-Zero: <https://arxiv.org/html/2509.18592>
- SpatialNav: <https://arxiv.org/html/2601.06806>

对 PRE_MAP_VLN 最有价值的不是单纯追逐最终 SR，而是把“预探索成本—地图质量—后续多任务收益”拆开报告。建议主表之外固定增加：预探索路径长度/时长、地图覆盖率、对象与房间召回率、每任务 Qwen 调用次数、缓存命中率，以及复用地图后的第 1/5/10 个任务平均成本。

## 7. 与本课题匹配的正式实验矩阵

R2R-CE 表回答“系统是否具备标准连续 VLN 能力”，但不能单独证明本课题的长指令、多任务顺序和终止观察位姿创新。最终论文应并列两套实验：

| 组别 | 地图/记忆 | 任务顺序 | 终止位姿 | 用途 |
|---|---|---|---|---|
| Open-Nav port | 无全局预探索地图 | 原始单指令 | 接近目标 | 无地图零样本下界 |
| VLN-Zero port | 符号场景图+轨迹缓存 | VLM 分解/缓存 | 接近目标 | 最接近的两阶段方法 |
| SpatialNav paper | 分层空间场景图 | 单条 VLN 推理 | 接近目标 | 空间先验前沿参考 |
| Ours w/o joint optimization | FALCON+Boxer+OccuSG | 固定原句顺序 | 最近可行点 | 证明联合优化贡献 |
| Ours w/o task-aware pose | 同上 | Task Graph Search | 最近可行点 | 证明任务相关观察位姿贡献 |
| PRE_MAP_VLN full | 同上 | 约束下全局重排 | 多候选任务相关位姿 | 主方法 |

长时程表在同一地图、同一任务集、同一 Qwen 后端与相同调用预算下运行，至少报告 3 scenes × 3 seeds。主指标为完整任务成功率、约束满足率、总路径长度和总耗时；辅助指标为条件分支正确率、执行位姿可见率、重规划次数、Qwen 调用数和单位成功任务成本。预探索成本单列，并额外报告地图复用到第 1/5/10 个任务时的摊销成本，避免把一次建图成本隐藏掉。
