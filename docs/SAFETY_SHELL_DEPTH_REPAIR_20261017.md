# 安全壳深度有效性修复

实现：repair_depth_validity.py按实际相机位姿将每个像素射线与显式collision_only的轴对齐安全壳求交。记录深度到达壳或位于壳后方，则整条测量置零；不生成最大距离端点，不保留该射线的自由清空。原碰撞物体和渲染物体均保留，RGB仍为原图；这不是删除RGB中的壳，而是拒绝把壳作为有效建筑深度。渲染可见性与有效测量语义分别处理。

run_habitat_falcon.py在发布深度前调用此函数，写入失效像素数。独立repair_collision_only.json将14个包围/封闭物体显式声明为collision_only和axis_aligned_box。旧repair.json未改，旧700秒数据与配置不变。新配置需以--scene-repair-config显式选择。相机起点必须与配置参考原点一致，否则拒绝运行，避免坐标错配。

验证：14个OBJ顶点变换后的边界与配置逐一吻合；遮挡壳前表面保留、命中/壳后失效、平行射线不误判、非有限深度置零均检查。8帧实际深度回归保存depth_validity_regression.json。未失效有限像素逐像素保持，失效像素全零。源码编译检查通过。实际命中比例依帧变化，不宣称整个ROI全是人工壳。

现有map_server直接投影分支对0深度continue；中值滤波分支在求中值后对0检查。因此需检查实际部署是否启用中值分支：邻域中值可能填补失效中心，尚未完成该分支的有效掩码透传验证。本次不修改冻结map_server或用已保存终态地图冒充重建。

边界：GPU不可用，未进行新传感器渲染/完整ROS重建；未晋升、未重跑700秒、未宣称305分割已修复。既有地图FREE历史不能通过删除最终壳面点撤销，需要以修正深度重新积分。安全壳有效性修复不等于恢复原建筑缺失墙面，也不证明所有房间轮廓正确。
