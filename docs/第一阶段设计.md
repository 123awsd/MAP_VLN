# 第一阶段设计与验收

## 数据流

`Habitat RGB-D/Pose → FALCON 探索轨迹 → 关键帧 → Boxer 3D boxes`

`关键帧 Depth/Pose → 2D 占据栅格 → OccuSG 房间多边形与邻接关系`

`Boxer boxes + OccuSG rooms → 房间语义场景图 JSON`

统一世界坐标采用右手系、Z-up、米制。相机输入采用 optical frame（X 右、Y 下、Z 前）。

## 运行时隔离

- Habitat：`.envs/habitat`，Python 3.9。
- Boxer：`.envs/boxer`，Python 3.12 + PyTorch CUDA。
- FALCON：`pre-map-vln/falcon-noetic:local`，ROS1 Noetic 容器。
- OccuSG：`pre-map-vln/occusg-humble:local`，ROS2 Humble 容器。
- 宿主机全局 Python、ROS、CUDA 和另一个项目均不修改。

## 开发场景验收结果

- HM3D scene：`00861-GLAQ4DNUx5U`。
- FALCON 驱动 Habitat 录制 40 个关键帧，轨迹长度 19.32 m。
- Boxer：163 个候选框，融合后 2 个静态实例。
- 占据图：256×321，0.05 m/pixel。
- OccuSG：11 个区域，11 条邻接边，处理耗时 30.4 ms。
- 场景图：11 个房间、2 个物体；识别出 bedroom，其余未知房间等待更完整探索和更丰富物体提示。

## 边界

本结果是公开 HM3D example 上的工程闭环，不是论文级数据集评测。正式实验仍应在获得 Matterport 凭据后下载 HM3D-Semantics minival，并固定一个多房间家庭场景。Boxer 物体中心通常位于被占据栅格排除的物体/墙面内，因此融合结果会显式记录 `nearest_centroid_fallback`；后续可升级为 3D box footprint 与房间边界的重叠分配。
