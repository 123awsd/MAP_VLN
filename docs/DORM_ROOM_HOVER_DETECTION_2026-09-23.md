# 宿舍成功 demo：悬停目标检测框视频

来源场次：`dorm_room_v3/check_pot_water_toiletpaper_cup_static_3s_xy_narrowcorridor_v7/flight_20260922_173316`，即本地标记“宿舍实验最后一次成功”的场次。

输出：场次目录下 `hover_detection_green_smooth_v2/rgb_detected_smooth.mp4`。

- 使用原始 1280×720、30 FPS RGB 视频，不使用 480p 预览版。
- 只在人工核对过的任务观察/悬停窗口显示检测框：厨房锅具、冰箱上的杯子、卫生纸、桌下矿泉水。
- 所有框统一绿色、5 px 粗边，只显示英文类别，不显示置信度数字。
- 框位置先做 5 帧中值滤波，再做对称 11 帧平滑；仅填补不超过 0.3 秒的内部漏检，不跨观察窗口外推。
- 检测框来自 Grounding DINO base 的逐帧预测。平滑与短漏检插值仅用于展示，不能当作每帧独立检测，也不代表在线识别或任务完成判定。
- 旧视频没有逐帧真实时间戳，因此悬停窗口依据视频画面和相邻帧运动人工核对，不宣称与 bag 飞控状态精确同步。

验证结果：输出 2556 帧、1280×720、30 FPS、85.2 秒；全片解码通过。显示框均位于对应目标的限定观察窗口内。

按后续反馈另生成 `hover_detection_green_raw_v4/rgb_detected_smooth.mp4`：保留绿色
5 px 粗框和无置信度数字的样式，但完全取消时间平滑、插值、漏检补框和固定尺寸。
每个显示框都是该帧的独立原始模型框，漏检帧不显示。

矿泉水的最终展示版为 `hover_detection_green_bigbottle_raw_v6/rgb_detected_smooth.mp4`。
最后一个观察窗口逐帧选择面积最大的整组矿泉水候选框，并要求面积至少 40000 px²；
没有整组大框的帧不显示，绝不退回单瓶小框。其他三个目标仍使用原始最高分框，全部不做平滑。
