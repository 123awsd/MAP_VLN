# 700 s map: automatic room semantics from measured RGB and Boxer

This stage takes the existing 700 s measured room partition and SAM3.1/Boxer object fusion as inputs. It does not rerun mapping, room segmentation, detection, or object fusion. For each automatic room region, it selects one or two measured RGB frames whose camera positions fall inside that region, associates fused 3D objects by their centers, and asks Qwen3-VL-Plus to classify that room independently. The model may return `unknown` when the evidence is insufficient. Geometry and object coordinates are not modified by the classifier.

The 2026-10-19 test prepared all 30 regions (7/13/10 by floor), 59 photos, and associated objects for 18 regions. All 30 model calls completed: 24 classifications passed the configured 0.65 confidence threshold and six were `unknown` (1-03, 1-06, 2-07, 3-04, 3-05, 3-09). The outputs are model predictions, **not ground-truth accuracy measurements**. The returned image indices and Boxer object IDs were checked against each room's submitted input. Room 2-07 deserves separate geometry review: its region is only 2.84 m², the selected views mostly show adjacent spaces, and its two associated Boxer objects are doors. This does not prove a segmentation error.

The English floor overview and six-room evidence contact sheet are generated by `scripts/render_multiview_room_semantics.py` and `scripts/render_unknown_room_review.py`. A copy of the overview is committed as [room_semantics_700s_overview.png](assets/room_semantics_700s_overview.png). `scripts/render_single_room_semantic_review.py` provides a detailed view of region 2-05. The complete generated files and per-room `semantic_results.json` remain under `outputs/stage1_pipeline_flow_20261019/automated_room_semantics/` and are ignored by Git with the rest of the experiment outputs.

Narrow unassigned seams are now persisted as **semantic footprints** by `scripts/build_room_semantic_footprints.py`, rather than filled only while plotting. It assigns a narrow seam only if exactly one existing room claims it. Across floors 1–3, it fills 385/748/1026 5 cm cells, respectively, while preserving the 7/13/10 room identities. Many filled cells are measured wall barriers (364/629/876); therefore, the source `labels`, `wall_barrier`, and navigable geometry remain unchanged. The saved `semantic_footprint_labels` are for semantic display and ownership, not free-space planning or room-area evaluation.

Reproduce locally from the retained input data:

```bash
.envs/habitat/bin/python scripts/classify_coverage700_rooms_multiview.py --all
# The next command sends indoor RGB and Boxer metadata to DashScope; it was
# explicitly authorized for this test. It uses per-room response caching.
.envs/habitat/bin/python scripts/classify_coverage700_rooms_multiview.py --all --execute
.envs/habitat/bin/python scripts/build_room_semantic_footprints.py
.envs/habitat/bin/python scripts/render_multiview_room_semantics.py
.envs/habitat/bin/python scripts/render_unknown_room_review.py
```

Local regression: `.envs/habitat/bin/python -m unittest tests/test_room_multiview_semantics.py` (two tests passed). The tests verify room/photo/object association and the production multimodal request and response contract with a mocked network call; they do not measure semantic accuracy.
