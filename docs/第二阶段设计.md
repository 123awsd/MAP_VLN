# 第二阶段：长时程多任务语义—几何联合规划

更新时间：2026-08-28

## 目标与完成状态

第二阶段把自然语言多任务指令转换为可执行 task graph，在第一阶段的房间、3D 物体框和占据地图上联合选择任务顺序与观察位姿，再由 Habitat 在线执行、视觉验证、更新地图并重规划。当前工程闭环已经通过自动验收。

默认演示指令为：先检查卧室床边的灯，再观察客厅电视；没有发现电视时检查柜子；门和椅子的先后不受约束。实际运行生成 5 个任务、1 条前置约束和 1 条条件规则。

## 与第一阶段的边界

第一阶段仍使用当前 00166 的稳定单层配置和既有产物，不把第二阶段的任务规划改动倒灌到探索器。第二阶段只消费第一阶段输出的占据图、房间/物体语义图和坐标变换。

因此，当前第二阶段的“3D 语义地图”用于目标框、区域高度和观察视锥约束；规划底层仍是二维自由栅格上的 A*，执行器也仍以 Habitat 的直接位姿设置完成仿真观测。候选位姿会记录 `height_fov_validated=true`、`height_collision_validated=false` 和 `collision_validation=2d_occupancy_only`，不能把它表述为完整三维自由空间或真实动力学飞行。

## 数据流

```text
自然语言 + scene graph
        ↓ qwen3.7-plus（严格 JSON、缓存、预算保护）
task graph
        ↓ box 几何 + 空间约束 + free grid + LOS/FoV
每任务候选观察位姿
        ↓ A* 路径代价 + Subset-DP
全局访问顺序 + 当前局部路径
        ↓ Habitat RGB-D + 本地 GPU OWLv2 在线执行
found / not_found → 更新 box 置信度 → 激活/跳过条件任务 → 重规划
        ↓
execution log + updated scene graph + RGB frames + ROS bag/RViz
```

## Task graph

`pre_map_vln.task_graph.v1` 中每个任务保存唯一 ID、动作、导航锚点 `target.label`、真正验证的 `verification_label`、房间/参照物提示、初始激活状态和完成条件。边表示先后约束，条件规则根据某个任务的 `found` 或 `not_found` 结果激活或跳过后继任务。

导航目标与验证目标被显式分开。例如“检查 counter 上有没有 cup”会导航到 counter 周围的观察位姿，但用 RGB/semantic 验证 cup，避免把参照物误当成检查对象。解析结果通过 schema、引用完整性、DAG 和条件规则校验；只有条件触发任务初始为 inactive，其余任务由前置边决定何时可执行。

Qwen 调用使用非思考模式和结构化 JSON，原始响应按指令与 scene graph 摘要哈希缓存。预算由环境变量配置，成功请求写入 `outputs/stage2/api_usage.json`；密钥只从 `.secrets/dashscope_api_key` 读取，目录和文件权限分别是 700/600，且被 Git 忽略。Qwen 不承担逐帧开放目标检测。

## 候选位姿与联合优化

每个任务先根据目标框、参照框和 `spatial_constraints` 生成任务相关区域，再在其周围按多个距离和方位采样候选点。当前 schema 额外保留 `region_type`、`observation_detail`、`height_range_m`、水平/垂直 FoV 和 yaw 容差，候选输出保留区域样本覆盖率、相对方位角和高度约束审计字段。

空间关系到几何规则的映射如下：

| 关系/区域 | 当前候选生成规则 |
|---|---|
| front / behind / left / right | 相对目标 box 朝向过滤方位角；yaw 指向目标中心 |
| facing | yaw 指向目标；不额外强制无人机位于目标正面 |
| on / support_surface | 以目标 box 顶面采样区域，并生成顶面上方的观察高度 |
| below / below_region | 以 box 底部下方区域采样，并生成较低观察高度 |
| near / surrounding_region | 目标周围环形区域 |
| between / between_region | 要求提供两个参照物，候选点落在两参照物连线及容差带内 |
| instance_region | 直接覆盖目标实例 box 的多高度样本 |

随后依次检查：

- 候选点位于自由栅格，且与障碍物保持安全距离；
- 到目标表面距离满足观察范围；
- 候选点到目标中心有占据栅格视线；
- yaw 朝向目标，满足空间关系方向和容差；
- 目标区域采样点落入水平/垂直 FoV，计算 `Q_cov=N_visible/N_region`；
- 若有参照物，则加入参照距离；`between` 还加入到参照连线的距离约束。

候选按终端代价排序，并保留空间分散的少量候选；当预算允许时，不同可行高度至少各保留一个候选。失败后，恢复器在同一位置按相对目标方位角选择顺时针或逆时针方向，连续访问相邻有效视角；同一位置耗尽后才切换位置或回到全局重规划。这专门避免旧逻辑在单个失败视角上反复选回同一个目标。

当前真正由底层验证的只有二维占据碰撞和二维 LOS。高度关系、FoV 和 z 候选是几何约束检查，不等价于 mesh/ESDF 三维碰撞验证；要实现文档中完整的飞行高度、地面/天花板净空和家具碰撞约束，还需要 3D free-space/ESDF 或 mesh collision 查询，并替换当前二维 A* 执行接口。

现有联合优化仍使用 A* 路径代价 + Subset-DP，同时考虑终端观察代价和 2.5D 的升降/yaw 时间近似。

路径代价由占据栅格上的 8 邻域 A* 计算，不使用欧氏距离替代绕障代价。Subset-DP 的状态同时包含已完成任务集合、末任务和末候选位姿，因此联合决定任务顺序与每个任务的终止观察位姿，同时严格满足 task graph 前置约束。在线执行默认采用基于代表候选的滚动时域求解：规划窗口默认包含 3 个当前可执行任务，每个物理位置首先保留 1 个动态代表位姿；若无可行规划，则依次扩展到 2 个和全部候选。可通过 `--planning-horizon-tasks` 和 `--representatives-per-location` 显式记录与复现该配置。

默认开发场景的初始 4 个活动任务共有 30 个候选位姿。联合结果为 4.466 m，固定语言顺序基线为 6.576 m，路径缩短 32.09%。

## 在线执行、视觉验证与重规划

`run_stage2_habitat.py` 使用真实 Habitat GPU renderer 沿 A* 路径移动，每一步记录连续 RGB，并在任务终点朝向目标。默认验证后端是隔离环境中的本地 OWLv2：常驻进程只加载一次权重，每 10 个运动帧做一次开放词表关键帧检测，终点再做目标确认；RGB 框结合对齐 depth 的稳健中值和相机位姿投影为世界坐标 3D box。投影结果还必须在 1 m 内关联到预探索 scene graph 的同类实例才进入在线 3D 地图，远距离误框只留审计记录。Semantic GT 只保留为对照，Qwen-VL 只保留为显式启用的复核或 `owlv2_qwen_fallback` 低置信度后备。

开发场景实测 OWLv2 启动约 4 s；模型常驻后终点帧平均 36.68 ms，在线关键帧平均 42.35 ms（含首帧余热），lamp/chair/door/television/cabinet 五类终点帧均检出。完整本地检测闭环为 74 帧、4 次任务访问/重规划、5.383 m、6.54 s；电视为 found，因此条件 cabinet 被正确跳过。该结果证明主检测链路没有调用 Qwen API。

默认受控演示仅把电视任务的阈值提高到 10,000 pixels，用来稳定覆盖 `not_found → 激活 cabinet` 分支，不会改变其他任务阈值。实测结果：5 个任务、5 次重规划、112 个运动 RGB 帧、总路径 7.569 m；chair、door、cabinet 为 found，lamp 和受控阈值下的 television 为 not_found。该阈值是条件分支回归测试，不代表电视检测失败。

## RViz 与 rosbag

本地开放词表包为 `outputs/bags/hm3d_stage2_open_vocab_complete.bag`，14.8 秒、411 条消息、约 45.2 MB。主 RViz 为白底掀顶式 3D/RGB 单窗口，并新增 `/stage2/open_vocab_boxes`，按 8 次在线关键帧事件逐步显示 RGB-D 投影框：

- 灰青色稀疏点云：去地板、去局部斜顶后的环境；
- 蓝色细线：已执行轨迹；紫色折线：当前全局 tour；琥珀色线：当前局部 A* 路径；
- 候选位姿、当前选中目标姿态、UAV pose 与真实相机视锥；
- 语义 box 随任务验证逐个更新：基础蓝、found 绿、not_found 红，线宽 0.050 m；
- 右侧实时 RGB 与当前任务/验证状态文本。

bag 完成后 RViz 不退出。倍速对 RGB、轨迹、box 和任务状态使用同一个 ROS 时钟：

```bash
./scripts/replay_stage2_rviz.sh hm3d_stage2_complete false 1.0
./scripts/replay_stage2_rviz.sh hm3d_stage2_complete false 2.0
./scripts/replay_stage2_rviz.sh hm3d_stage2_open_vocab_complete false 1.0
```

## 多地图测试边界

本机已有官方 HM3D example 包中的 3 个场景，全部使用真实 Habitat navmesh/几何地图运行 A*、候选位姿、Subset-DP 和动态条件状态机：

| Scene | Navmesh area | Joint | Fixed-order | Improvement |
|---|---:|---:|---:|---:|
| 00337-CFVBbU9Rsyb | 186.37 m² | 9.660 m | 13.457 m | 28.22% |
| 00770-NBg5UqG3di3 | 299.43 m² | 54.536 m | 77.491 m | 29.62% |
| 00861-GLAQ4DNUx5U | 125.91 m² | 31.982 m | 44.256 m | 27.73% |

其中 `00861` 使用第一阶段真实 Boxer scene graph，并完成真实 RGB/Semantic 在线闭环。另两个场景缺少各自的 Boxer 结果，因此多地图脚本只用明确标注的 synthetic semantic anchors 隔离验证几何规划泛化；不能把这两项表述为真实语义检测精度实验。用户提供的单个 Matterport 值不足以完成当前 token-ID/token-secret 双字段认证，所以没有擅自下载 minival。正式论文评测仍需完整 Matterport 凭据后，逐地图运行第一阶段产生真实 scene graph。
