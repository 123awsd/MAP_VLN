# Fig. 7 home scene: 3D planning draft

This is an illustrative, experimental calculation over `/home/uav/下载/home_-_p3.glb`, not a flight log, measured map, MINCO trajectory, or final paper figure. The source scene and its material assets are preserved in the Blender file.

Four manually estimated object boxes identify bedroom bed (A), study desk (B), bathroom sink (C), and living-room sofa (D). Candidate poses are computed with `stage2.candidate_poses.generate_candidates` from the `real-fly` branch and checked using a 3D `VoxelMap3D`. Up to 90 outputs are generated per target; three are retained with a preference for distinct azimuths. The sink has only two feasible azimuths in this calculation, so two retained views share one azimuth but differ in height. The remaining viewpoints need visual and geometry review.

`stage2.joint_planner.plan_joint_mission` and `CoarseAstar3D` select task order and poses and compute 3D voxel-grid paths. Straight endpoint connectors have independently passed `VoxelMap3D.line_is_valid` against the same draft map. The lines are A* paths, not MINCO, and the calculation does not demonstrate physical flight or a dynamically feasible trajectory.

Important assumptions: GLB model units are assumed to be inches (0.0254 m/unit), without source confirmation. Surface occupancy is based on 1,668,697 random mesh-surface samples; all other cells in the bounded map are assumed free, including potentially unobserved or interior-of-object regions. Sampling can miss geometry; this map is not a verified collision map. The planner uses an illustrative small drone, 0.10 m radius plus 0.05 m safety margin and 0.10 m resolution, not the default project vehicle profile. These assumptions and the manually estimated 3D boxes must be validated before claiming collision-free motion or using the figure as evidence.

The `planning_3d_draft.blend` file has real 3D curve objects: target boxes, camera-apex frusta, candidate and selected poses, and A* path segments. The PNG is an overhead preview, not the underlying representation. Selected frusta are dark blue, unselected are light blue, target boxes are orange, and the start is red. The paper's installed figure has not been changed.

To reproduce locally, extract `stage2` and `config/semantic_aliases.json` from the repository's `real-fly` branch into `/tmp/fig7_project_code`, run `sample_scene.py` and `plan_3d_draft.py` with the `env_isaaclab` Python environment, then run `select_targets.py` and `build_3d_draft.py` in Blender background mode. Keep the mesh, target boxes, candidate results, and path generation together; do not substitute trajectories from another scene.

## Height-limited review revision

`planning_3d_height_limited.blend` and `.png` remove B3 and C2, preserve all other review labels, and replan with a 0.65–1.75 m altitude band under the same unverified GLB-unit assumption. The resulting voxel-center path has z between 0.85 and 1.65 m; selected candidate poses also satisfy the band. The planned order is D3 → B1 → C3 → A1. The 0.15 m clearance used in the first draft disconnected the bathroom in the sampled map; this revision uses a 0.10 m radius and 0.04 m margin (0.14 m). This parameter change is an illustration assumption, not a verified aircraft specification.

`mesh_intersection_height_limited.json` reports zero centerline segment intersections with the complete original GLB triangle mesh. `mesh_clearance_height_limited.json` reports sampled mesh distances with at most 0.04 m spacing; the smallest sampled value is approximately 0.175 m. Mesh sampling, unit assumptions, and modeled vehicle size still prevent a real-flight safety claim. This is A* and has not undergone MINCO smoothing.

## Conditional task and MINCO revision

`conditional_minco_draft.blend` and `.png` use the bedroom start and keep B3/C2 removed. `conditional_plan.py` invokes the actual project subset-DP planner and `MissionState`: A/B/C initially active, D inactive; A `not_found` activates D; `found` skips D. In this geometry the computed initial order is A → C → B and, after A, the computed updated order is C → B → D. The example represents a simulated observation, not an actual flight. In this revision gray is the simulated executed prefix Start → A, blue is the updated future plan, and orange is the newly active D viewpoint. C → B happens in both plans; the changed conditional behavior is D's activation, not a fabricated reordering.

`minco_trial/initial_minco.txt` and `updated_minco.txt` are newly generated project `full_smooth_mission` polynomial artifacts from this scene's own A* guides and sampled collision cloud, not the original figure's polynomials. `sampled_minco.json` and the Blender curves derive directly from these coefficients. Both runs reported global MINCO SAFE against the downsampled PCD; detailed logs are in `minco_trial/`. An independent sampled audit in `independent_audit.json` reports altitude ranges 0.799–1.616 m and 0.800–1.610 m, within the requested 0.65–1.75 m band. Original GLB mesh proximity sampling gives minimum distances of roughly 0.187 m and 0.182 m. Four updated-trajectory samples and five small sample edges fail the conservative 0.1 m voxel predicate; no full voxel-clearance claim is made. The PCD is surface sampled, the mesh is not proven watertight, the unit scale is assumed, and aircraft parameters are illustrative. Resolve the map-predicate disagreement and verify the scale before using this as a final figure or flight result.
